## 二、部署架构

```
              https://game.011208.shop
                        │ 443 SSL
                        ▼
                ┌───────────────┐
                │     nginx     │  sites-enabled/game
                │               │
   /  /assets/* │  静态文件      │  root: /var/www/draw-guess
                │               │
   /api/*       │  反向代理 ────┼──► 127.0.0.1:4000 (PM2: draw-guess)
   /socket.io/* │  反向代理 ────┘
                └───────────────┘
```

- **前端**：构建产物部署在 `/var/www/draw-guess/`，nginx 直接托管，SPA fallback。
- **后端**：`/root/draw-and-guess/server/src/index.js`，PM2 守护，监听 `127.0.0.1:4000`，由 nginx 反代 `/api/` 与 `/socket.io/`。

## 五、部署流程

### 5.1 部署前端（每次代码变更后）

构建产物为带 hash 的文件名（如 `index-CmaDY4-J.js`），**部署后需删除旧 hash 文件**。

```bash
# 1) 构建（在 client/ 下）
npm run build
# 记下 dist/index.html 引用的新文件名，例如：
#   <script src="/assets/index-XXXX.js">
#   <link  href="/assets/index-YYYY.css">

# 2) 备份线上前端
sshpass -p "$PW" ssh $OPT $H \
  'TS=$(date +%Y%m%d-%H%M%S); cp -r /var/www/draw-guess /root/deploy-backups/front-$TS; echo "BACKUP=/root/deploy-backups/front-$TS"'

# 3) 上传 index.html + 新的 js/css（按实际 hash 替换 XXXX/YYYY）
sshpass -p "$PW" scp $OPT dist/index.html $H:/var/www/draw-guess/index.html
sshpass -p "$PW" scp $OPT dist/assets/index-XXXX.js dist/assets/index-YYYY.css $H:/var/www/draw-guess/assets/

# 4) 删除线上旧 hash 文件（仅保留最新一组），并验证
sshpass -p "$PW" ssh $OPT $H 'bash -s' <<'EOF'
  cd /var/www/draw-guess/assets
  # 列出当前文件，手动确认后删除旧的；示例：
  ls -la
  # rm -f index-<旧hash>.js index-<旧hash>.css
  echo "线上 HTML 引用："
  grep -oE 'index-[A-Za-z0-9_-]+\.(js|css)' /var/www/draw-guess/index.html
EOF
```

> 前端是纯静态，无需重启任何服务，上传即生效。

### 5.2 部署后端（仅当 server/ 代码变更）

```bash
# 1) 备份线上后端
sshpass -p "$PW" ssh $OPT $H \
  'TS=$(date +%Y%m%d-%H%M%S); mkdir -p /root/deploy-backups/$TS; cp /root/draw-and-guess/server/src/index.js /root/deploy-backups/$TS/index.js.bak; echo "BACKUP=/root/deploy-backups/$TS"'

# 2) 上传变更的源文件（按实际改动文件）
sshpass -p "$PW" scp $OPT ../server/src/index.js $H:/root/draw-and-guess/server/src/index.js
# 如改了 game.js / words.js 一并上传

# 3) 重载：PM2 已开启 watch 模式，覆盖源文件会自动重启加载新代码
#    （手动 pm2 restart 见“运维注意”——可能触发 SSH 断连）
```

## 六、nginx 配置

启用站点 `/etc/nginx/sites-enabled/game`（软链到 `sites-available/game`）：

```nginx
server {
    server_name game.011208.shop;
    root /var/www/draw-guess;
    index index.html;

    location /api/        { proxy_pass http://127.0.0.1:4000; proxy_http_version 1.1; proxy_set_header Host $host; proxy_set_header X-Real-IP $remote_addr; }
    location /socket.io/  { proxy_pass http://127.0.0.1:4000; proxy_http_version 1.1; proxy_set_header Upgrade $http_upgrade; proxy_set_header Connection "upgrade"; proxy_set_header Host $host; }
    location /            { try_files $uri $uri/ /index.html; }   # SPA fallback

    listen 443 ssl;
    ssl_certificate     /etc/letsencrypt/live/game.011208.shop/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/game.011208.shop/privkey.pem;
}
server {                                  # 80 → 443 跳转
    if ($host = game.011208.shop) { return 301 https://$host$request_uri; }
    server_name game.011208.shop; listen 80; return 404;
}
```

要点：
- `try_files … /index.html` 是 SPA 的关键，保证刷新 `/game/:id` 不 404。
- WebSocket 走 `/socket.io/`，必须带 `Upgrade`/`Connection` 头。
- 改配置后：`nginx -t && systemctl reload nginx`。

- ⚠️ `pm2 show` / `pm2 restart` 可能触发 SSH 断连（见运维注意），优先依赖 watch 自动重载 + `pm2 list` 确认。

```bash
# 前端回滚（用对应时间戳）
sshpass -p "$PW" ssh $OPT $H \
  'rm -rf /var/www/draw-guess/* && cp -r /root/deploy-backups/front-<时间戳>/* /var/www/draw-guess/'
```

## 十、运维注意事项（重要 / 踩过的坑）

1. **SSH 进程枚举命令会触发断连** ⚠️
   在本服务器上执行 `ss -tlnp`（带 `-p`）、`pm2 show`、`pm2 restart` 等读取 `/proc` 进程详情的命令，会被服务端直接断开连接（`Connection closed by ... port 22`，exit 255）。
   - **规避**：用 `ss -tln`（不带 `-p`）；查进程用 `pm2 list`（可用）；拿脚本路径读 `/root/.pm2/dump.pm2`；查状态读日志文件；能用文件操作就别用进程枚举命令。

2. **PM2 watch 自动重载**
   `draw-guess` 开启了 `watching: enabled`。`scp` 覆盖源文件后会自动重启加载新代码。因此即使手动 `pm2 restart` 因断连未完成，新代码也已生效——用 `pm2 list` 看 `uptime` 是否归零确认即可。重启计数 `↺` 偏高多为 watch 触发，非崩溃。

3. **本地 dist 不会自动清空**
   `vite build` 会在 `client/dist/assets/` 累积历史 hash 文件。部署时**只精确上传当前 `index.html` 引用的那一组** js/css，**切勿** `scp -r` 整个 assets，否则会把过期文件一并传上线。

4. **浏览器缓存**
   文件名 hash 变化天然破缓存，但 `index.html` 本身可能被缓存导致仍加载旧 js。排查时用强刷（`Ctrl+Shift+R`）或无痕窗口；可考虑给 nginx 的 `index.html` 加 `Cache-Control: no-cache`。

5. **本地开发端口**
   后端默认 `4000`。本地若被占用，用 `PORT=4100 node src/index.js` 换端口启动。

## 十一、常见问题排查

| 现象 | 排查方向 |
|------|----------|
| 访问仍是旧版本 | `curl https://game.011208.shop/` 看 hash 是否为新；浏览器强刷/无痕；确认旧 hash 文件已删 |
| 刷新 `/game/:id` 出现 404 | nginx 缺 SPA fallback，检查 `location / { try_files $uri $uri/ /index.html; }` |
| WebSocket 连不上 / 实时不同步 | 检查 `/socket.io/` 反代及 `Upgrade`/`Connection` 头；确认后端 4000 在线 |
| 后端改了不生效 | `pm2 list` 看 `uptime` 是否归零；`cat /root/.pm2/logs/draw-guess-error.log` 看报错 |
| `/api/health` 不通 | 后端进程是否 online；nginx `/api/` 反代是否正确 |
| 房间/分数丢失 | 后端纯内存存储，进程重启即清空，属预期；如需持久化需引入数据库 |
| SSH 命令执行就断开 | 见运维注意 1，改用非进程枚举命令 |
