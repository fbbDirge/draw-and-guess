# 你画我猜（Draw & Guess）技术文档

> 多人实时绘画猜词游戏。画家根据词作画，其他玩家通过聊天框猜词，按速度与人数计分。

---

## 一、项目概述

- **类型**：多人实时在线游戏（Web）
- **核心玩法**：每轮随机一名玩家当「画家」选词作画，其余玩家在限定时间内猜词；猜对得分，越快越高，画家依据被猜中情况得分。
- **房间制**：6 位数字房间号，支持创建/加入/重连，房主控制开始与再来一局。
- **数据存储**：**纯内存**（服务端 `Map` 保存房间状态），无数据库、无持久化。进程重启后房间丢失。
- **实时通信**：基于 Socket.IO 的双向事件。

## 四、整体架构

```
┌─────────────┐   Socket.IO (ws)   ┌──────────────────┐
│  Browser    │ ◄────────────────► │  Node + Socket.IO │
│  React SPA  │   /socket.io/      │  (port 4000)      │
│             │                    │                   │
│ useSocket   │   HTTP /api/*      │  RoomManager      │
│  (单一 ctx) │ ◄────────────────► │  GameLogic        │
└─────────────┘                    │  (内存 Map)        │
      ▲                            └──────────────────┘
      │ 静态资源 (HTML/JS/CSS)
      │
┌─────────────┐
│   nginx     │  /var/www/draw-guess + 反代 /api/ /socket.io/ → :4000
└─────────────┘
```

- **前端**：单页应用，所有页面共享 `App` 中创建的**唯一** `useSocket()` 实例（`ctx`），因此 `room`/`round`/`countdown` 等状态跨路由保持。
- **后端**：每个房间一个 `GameLogicProxy`（封装 `GameLogic` + 通过回调向房间广播事件），房间状态存于 `RoomManager.rooms`（`Map`）。

## 五、前端设计

### 5.1 路由（App.tsx）

| 路径 | 页面 | 说明 |
|------|------|------|
| `/` | Home | 创建/加入房间 |
| `/room/:id` | Room | 房间等待，准备/开始 |
| `/game/:id` | Game | 游戏进行 + 弹框 |
| `*` | → `/` | 兜底重定向 |

页面间通过 effect 自动跳转：
- Home：检测到 `room` 非空 → `/room/:id`
- Room：`countdown>0 || room.status==='playing'` → `/game/:id`
- Game：游戏重置（`ddg:gameReset` 事件）→ 回 `/room/:id`

### 5.2 状态管理：useSocket.ts（核心）

整个应用的 socket 连接与游戏状态集中在此 hook，对外暴露状态与方法。关键状态：

| 状态 | 含义 |
|------|------|
| `connected` | socket 是否已连接 |
| `room` | 当前房间（id/players/status/hostId…） |
| `round` | 当前回合信息（含本人是否画家 `isDrawer`） |
| `wordChoices` | 画家选词数据（仅画家收到） |
| `roundEnd` | 本轮结束数据（答案/猜对者/快照） |
| `gameOver` / `finalScores` | 游戏结束 + 最终排名 |
| `countdown` | 开局倒计时（`game_starting` 设 3，`round_start`/离开时重置 -1） |
| `canvasStrokes` / `canvasVersion` | 画布线段 + 版本号（清空时自增，用于丢弃过期笔画） |
| `lastClear` | 清空时间戳（触发 Canvas 重绘） |

暴露的方法：
- `emit(event, data)`：自动附带 `playerToken` 后发送
- `leaveRoom()`：**同步清空全部状态**（room/round/countdown/gameOver…）再发 `leave_room`，避免离开后被自动跳转逻辑弹回

### 5.3 Canvas.tsx（绘图）

- 坐标归一化为 `0~1` 比例存储，重绘时乘以画布宽高，适配任意尺寸/缩放。
- 画家绘制时每 ~35ms 把一段两点线段经 `onStroke` 上报（`draw_stroke`）；猜测者只读，接收线段累积绘制。
- **strokeId 分组**：每一「笔」（mousedown→mouseup）生成唯一 `strokeId`，该笔所有线段携带，用于撤回。
- 暴露 imperative 方法：
  - `forceClear()`：清本地线段 + 清画布像素
  - `undoLast()`：弹出本地最后一笔并重绘，返回其 `strokeId`（供上报）

### 5.4 页面组件

- **Home**：昵称 + 创建（人数上限/每轮时间）/ 加入（房间号）/ 最近房间。
- **Room**：玩家列表、准备状态、房主踢人、开始游戏、离开房间。
- **Game**：顶部回合信息/计时；画布 + 画家工具（颜色/笔刷/橡皮擦/撤销/清空）；玩家积分条；侧栏计分板 + 聊天；以及选词、本轮结束、游戏结束三种全屏弹框。

## 六、后端设计（game.js / index.js）

### 6.1 RoomManager

管理房间生命周期，`this.rooms: Map<roomId, room>`。核心方法：
- `createRoom / joinRoom / kickPlayer / removePlayer / setReady / canStart`
- 房间号：6 位随机数字（冲突重试，兜底 uuid 前 6 位）
- **重连**：玩家持 `playerToken`，`joinRoom` 时若 token 已存在则迁移旧玩家记录（id/分数/已猜状态）到新 socket.id，实现断线重连不丢分。

### 6.2 GameLogic

纯游戏逻辑（不直接碰 socket），通过 `_on*` 回调通知外层广播。核心：
- `startGame`：`totalRounds = 玩家数`，重置分数，进入首轮准备
- `_prepareNextRound`：轮换画家（`currentDrawerIndex`），生成 4 个不重复候选词
- `pickWord`：画家选词，`canvasVersion += 1`，启动回合计时器
- `submitGuess`：判定猜词、计分、控制提前结束（见计分规则）
- `_endRound`：结算画家奖励，判断是否最后一轮
- `_endGame` / `_getFinalScores`：生成最终排名
- `resetGame`：再来一局，回到 `waiting`

### 6.3 GameLogicProxy（index.js）

每房间一个，桥接 `GameLogic` 回调到 `io.to(roomId).emit(...)`：
- `_onRoundEnd`：广播 `round_end`；若是最后一轮，**延迟 5s** 再广播 `game_end`
- `_onNextRound`：广播下一轮 `word_choices`
- `_onTimerShorten`：广播计时缩短

## 七、游戏完整流程

```
创建/加入房间 ──► Room 等待（准备）
      │ 房主 start_game
      ▼
game_starting(countdown=3) ──► 各端跳转 /game
      │ 3s 后
      ▼
画家收到 word_choices ──► pick_word(选词，可换2次)
      │
      ▼
round_start（画家收到含 word，猜词者只有 wordLength）
      │  画家：draw_stroke / clear_canvas / undo_stroke
      │  猜词者：submit_guess
      ▼
本轮结束触发条件（任一）：
  - 全员猜对 → 2s 后结束
  - 仅剩 1 人未猜对 → 计时缩短为 10s
  - 计时到 0
      │
      ▼
round_end（公布答案/猜对者/画作快照）
      ├─ 非最后一轮：5s 后自动 _prepareNextRound → 下一位画家 word_choices
      └─ 最后一轮：room.status='finished'，5s 后 game_end（最终排名）
      │ 房主 play_again
      ▼
game_reset ──► 各端回到 /room 等待，分数清零
```

- **轮数**：`totalRounds = 玩家数`，每人轮流当一次画家。
- **画布版本** `canvasVersion`：每次选词/清空自增；猜词者收到 `draw_stroke` 时若其 `canvasVersion` 小于本地版本则丢弃（防止清空后过期笔画重现）。

## 八、Socket.IO 事件协议

### 客户端 → 服务端

| 事件 | 载荷 | 说明 |
|------|------|------|
| `create_room` | `{username, playerToken, maxPlayers, roundTime}` | 创建房间 |
| `join_room` | `{roomId, username, playerToken}` | 加入/重连 |
| `toggle_ready` | — | 切换准备 |
| `kick_player` | `{playerId}` | 房主踢人 |
| `start_game` | — | 房主开始 |
| `pick_word` | `{choiceIndex}` | 画家选词 |
| `refresh_words` | — | 画家换一批词（限 2 次） |
| `draw_stroke` | `{points, color, size, strokeId}` | 上报一段线段 |
| `clear_canvas` | — | 清空画布 |
| `undo_stroke` | `{strokeId}` | 撤回一笔 |
| `submit_guess` | `{guess}` | 提交猜测 |
| `play_again` | — | 房主再来一局 |
| `leave_room` | — | 离开房间 |

> 所有 emit 由前端 `emit()` 统一附加 `playerToken`。

### 服务端 → 客户端

| 事件 | 载荷（要点） | 说明 |
|------|------|------|
| `room_created` / `room_joined` | `{roomId, player, room}` | 创建/加入成功 |
| `room_update` | `{room}` | 房间状态变更 |
| `kicked` | `{message}` | 被踢出 |
| `game_starting` | `{countdown}` | 开局倒计时 |
| `word_choices` | `{drawerId, drawerName, choices[], refreshLeft, round, totalRounds}` | 选词（仅画家） |
| `round_start` | `{round, totalRounds, drawerId, drawerName, word?, wordLength, category, isDrawer, canvasVersion}` | 回合开始（猜词者无 `word`） |
| `draw_stroke` | `{points, color, size, strokeId, canvasVersion}` | 转发给猜词者 |
| `canvas_cleared` | `{canvasVersion}` | 清空（广播全员） |
| `undo_stroke` | `{strokeId}` | 撤回（转发给猜词者） |
| `guess_result` | 对：`{correct:true, playerId, playerName, scores, allGuessed}`；错：`{correct:false, guess}` | 猜测结果 |
| `chat_message` | `{system?, userName?, message, isGuess?}` | 聊天/系统消息 |
| `timer_shorten` | `{seconds}` | 计时缩短 |
| `round_end` | `{word, category, drawerName, correctGuessers[], scores, gameEnding, finalScores?}` | 本轮结束 |
| `game_end` | `{finalScores[]}` | 游戏结束 |
| `game_reset` | `{room}` | 再来一局，回到等待 |
| `room_closed` / `left_room` / `error` | `{message}` | 房间关闭/已离开/错误 |

## 九、计分规则

| 角色 | 时机 | 公式 |
|------|------|------|
| 猜对者 | 猜中即时 | `max(10, round(50 × (1 − 已用时/每轮时长)))`，越快越高，保底 10 |
| 画家 | 每有人猜中即时 | `round(30 × (已猜对人数 / (总人数−1)))` |
| 画家 | 本轮结束额外奖励 | `已猜对人数 × 10` |

提前结束控制：
- **全员猜对**：清除计时，2s 后结束本轮。
- **仅剩 1 人未猜对**：计时缩短为 10s（`timer_shorten`）。

## 十、断线重连机制

- 前端首次访问生成 `playerToken`（`crypto.randomUUID()`）存 localStorage，之后每次 emit 携带。
- 断线后重新 `join_room`：服务端发现 `playerToken` 已存在 → 把旧玩家记录（含分数、是否已猜对、房主身份）迁移到新 `socket.id`，实现**不丢分重连**。
- 前端 socket.io 配置 `reconnection: true, reconnectionAttempts: Infinity`，断线自动重连。

## 十一、Bug 修复记录（本轮）

| # | 问题 | 根因 | 修复 |
|---|------|------|------|
| 1 | 撤回完全失效 | 笔画被拆成无分组的两点线段；`socket.to` 把画家自己排除；猜词者 pop 永远为空的本地数组 | 引入 `strokeId` 分组；画家本地 `undoLast()`；猜词者按 `strokeId` 过滤线段重绘 |
| 2 | 清空不同步 | （排查确认）逻辑本就正确：`canvas_cleared` 广播 + `setCanvasStrokes([])` + `forceClear` | 无需改动，实测验证通过 |
| 3 | 最后一轮作品弹框遮挡排行/不消失 | `game-over` 与 `round-end` z-index 同为 105；`round_end→game_end` 靠裸 `setTimeout` 易丢失 | `game-over` z-index 提至 120；前端用 `round_end` 自带 `finalScores` 起 6s 兜底切换 |
| 4 | 「返回首页/离开」被弹回游戏页 | `countdown` 设为 3 后永不重置 → Room/Game「`countdown>0` 即跳游戏」effect 永久生效；离开为异步，Home 见旧 `room` 跳回 | 新增 `leaveRoom()` 同步清空全部状态；`round_start` 重置 `countdown=-1` |
| 5 | 「再来一局」卡空白游戏页 | `game_reset` 无任何导航，玩家停在无 `round` 的空 Game 页，房主无重开入口 | `game_reset` 广播 `ddg:gameReset` 事件，Game 监听后导航回 `/room/:id` |
